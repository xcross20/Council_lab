# RETHINK — Evidence-triggered architectural reconsideration

## Purpose
Challenge whether the current approach remains the simplest defensible means of achieving MISSION.md and STRATEGY.md. RETHINK is **not** a permanent debate or a routine approval gate on every task.

## Triggers
- Three unsuccessful bounded repair attempts, or the active task's lower configured limit.
- Two recurring failures with the same root cause across accepted tasks.
- Divergence between Git, SQLite, or signed/content-addressed verification artifacts.
- Reviewer identifies a new material security/authorization or scientific-integrity risk.
- Demonstrated regression in verified completion, repair cost or cycle time against a recorded baseline.
- Evidence an established tested component could replace materially redundant new infrastructure.
- Material contradiction between approved mission/strategy and proposed NEXT.md work.

## Inputs
Immutable work-order contract, exact SHAs, full failed attempt history, independent review findings, existing tests, cost/elapsed metrics, and relevant architectural constraints. Explicitly distinguish verified observations from speculation.

## Questions
1. Is the system solving the right problem, or optimizing an artifact of the benchmark?
2. Is the suspected root cause supported by independent evidence?
3. Is another bounded repair appropriate, or should a discriminating test come first?
4. Can the change be implemented with existing components rather than new orchestration?
5. Would the proposal weaken authority, hidden evaluation, evidence validation, or safety gates?
6. Is the additional complexity justified by measured improvements?

## Outputs — advisory, schema to be implemented later
- CONTINUE: proceed with an already authorized bounded repair/order.
- REVISE_PLAN: propose modified work order within existing approved authority; controller validates scope, budget and acceptance invariants.
- ESCALATE: unresolved scientific-methodology, scope/authority, security or budget decision requires human approval.
- SAFETY_STOP: integrity/security invariant violated; controller stops without relying on model consent.

Rethink recommendations are model-generated proposals only. The deterministic Controller retains decision rights. RETHINK never changes frozen research scoring or adds permission unilaterally.

## Records
Write reason, trigger, evidence references, alternatives, dissent, estimated costs, recommended action and controller disposition into the run's evidence ledger. Do not rewrite historical decisions or accepted attempts.

## Anti-patterns
No incessant councils; no automatic requirement to consult 27 prompt roles; no superficial consensus; no re-labeling failed tests as successes; no architecture rewrite after a single ordinary bug.
